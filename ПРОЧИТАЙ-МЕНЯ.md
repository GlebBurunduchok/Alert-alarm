# Тихий ранок — автоматическое обновление и push

Сайт уже обновлён: https://tykhyi-ranok-api.glebkrupnik.workers.dev/

## Что изменилось

1. Кнопка ручной проверки тревог удалена. API проверяется автоматически раз в минуту.
2. При наступлении времени будильника и активном выбранном уровне тревоги сервер отправляет push: жёлтый, красный либо оба уровня. Пока уровень не меняется, сообщение не повторяется каждую минуту. Параллельно на открытой странице есть сообщение об отсрочке.
3. Звук пытается активироваться при загрузке. Если браузер блокирует автозапуск, он включается при первом касании страницы или нажатии клавиши, без отдельного обязательного нажатия «Увімкнути звук». При ошибке остаётся кнопка для повторной попытки. Полностью убрать требование взаимодействия со стороны браузера нельзя.
4. «Новий будильник» подставляет текущие часы и минуты в выбранном часовом поясе. Если сохранить этот же уже наступивший час, следующее срабатывание будет в следующий подходящий день — это по-прежнему обычный выбор времени, а не немедленный тест.

## Включить push на телефоне

1. Откройте сайт. На iPhone добавьте его на главный экран и откройте через этот значок. Требуется поддерживающая Web Push версия iOS (16.4 или новее).
2. Выберите область, если она ещё не сохранена.
3. Настройки → «Сповіщення про відкладений будильник» → «Увімкнути push-сповіщення». Разрешите уведомления в системном запросе. Этот запрос нельзя подтвердить автоматически вместо вас.
4. Нажмите «Надіслати тест» и проверьте уведомление на телефоне. Если вы ранее запретили уведомления, сначала измените разрешение в настройках браузера/системы.
5. Сохраните будильник с ожиданием нужных уровней. Изменения передаются на сервер автоматически. Сообщение «Push увімкнено · розклад синхронізовано» подтверждает сохранение. При ошибке нужно подключиться к сети и открыть страницу.

Серверные уведомления могут приходить и с закрытой страницей, если телефон имеет доступ к интернету и разрешения действуют. Доставка зависит от браузера, службы push, настроек уведомлений и энергосбережения; мгновенная доставка не гарантируется. Звук самого будильника при закрытой или спящей вебстранице эта версия не обеспечивает.

Сервер не знает, что будильник был изменён на телефоне без интернета, пока страница не подключится и не синхронизируется. Поэтому до синхронизации возможно уведомление по прежнему расписанию. Сообщения имеют короткий срок доставки. Серверное наблюдение за сохранёнными будильниками ограничено 14 днями с последней синхронизации; открытая страница продлевает его. Для выключения есть кнопка «Вимкнути» в настройках уведомлений.

Без актуальных данных API будильник на активной странице звонит по времени, как и раньше. Push не заменяет системный будильник.

## Убрать старый сайт GitHub

Рекомендуемый рабочий адрес теперь Cloudflare. Чтобы выключить старую публикацию:

1. Откройте репозиторий https://github.com/glebburunduchok/Alert-alarm .
2. Actions → выберите каждый старый процесс публикации/обновления отчётов → меню «…» → Disable workflow. Это остановит автоматическое повторное размещение старого сайта.
3. Settings → Pages → меню «…» возле действующей публикации → Unpublish site.
4. Удалите с главного экрана телефона старый значок, ведущий на github.io, и используйте значок Cloudflare.

Unpublish убирает опубликованную страницу, исходные файлы остаются в репозитории. Удалять весь репозиторий для этого не нужно. Для удаления отдельных старых файлов можно открыть файл в GitHub → меню «…» → Delete file → Commit changes; это не требуется для работы нового сайта.

Официальные инструкции:
https://docs.github.com/en/pages/getting-started-with-github-pages/unpublishing-a-github-pages-site
https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows

## Если хотите оставить GitHub Pages

В ZIP также есть github-pages. Загрузите её содержимое в корень репозитория с заменой, включая скрытую папку .github. Старые другие workflow обновления отчётов отключите. Settings → Pages → Source → GitHub Actions; затем Actions → Deploy website → Run workflow.

Публикация должна включать index.html, sw.js, manifest.webmanifest и icon.svg. В настройках сайта укажите адрес API-сервера https://tykhyi-ranok-api.glebkrupnik.workers.dev без дополнительного пути. Используйте один адрес приложения для будильников, чтобы не создавать два независимых расписания на двух ярлыках.

## Файлы и обновления Cloudflare

cloudflare-server содержит весь сервер, вебстраницу, сервис-воркер, манифест и список зависимостей. Для будущего повторного размещения распакуйте новую версию, откройте эту папку и запустите update.cmd. Установятся зависимости из package-lock.json и обновится ваш Worker. Существующий API-токен на Cloudflare сохраняется, вводить его повторно не нужно.

setup.cmd предназначен для первоначальной настройки аккаунта/токена. Сам токен не включён в архив. Ключи Web Push автоматически создаются и сохраняются в приватном серверном хранилище. API-токен, приватные ключи и подписки не отдаются публичной странице; на устройстве хранится только его собственный ключ управления уведомлениями.

## Проверено

Публикация Cloudflare, HTTP 200 от API и публичного ключа push, настоящий запуск сохранения/отмены изолированного серверного расписания, интерфейс редактора с текущим временем и автоматическая активация звука после взаимодействия в браузере.

Автоматические тесты: шифрование Web Push и VAPID; выбор уровня; момент наступления будильника; отсутствие повторов при неизменном уровне; повтор после ошибки доставки; повторяющиеся будильники; удаление/отключение расписания; защита управления устройством; срок наблюдения; ограничения адресов push-сервисов; прежние проверки расписания, API и офлайн-режима.

Фактическое получение уведомления и громкость на вашем физическом телефоне ещё нужно проверить кнопкой «Надіслати тест» и тестовым будильником.
